# PatchManager v1.9.1

Prepared: 2026-11-04. Publication and live provider smoke tests are separate gates.

This patch release fixes NVD lookups when the configured API key has expired or
been revoked. Report shapes, exit codes and configuration are unchanged from 1.9.0.

## Changes

- NVD answers `404 Invalid apiKey.` for an expired or revoked `NVD.ApiKey`. On
  1.9.0 every lookup failed, was retried and logged a warning, so the inventory
  scan used its whole budget and mapped nothing. The key is now dropped for the
  rest of the run after the first rejection, with one warning, and lookups
  continue without it at the public rate limit (at least 6.5 seconds apart).
- Other NVD 404 responses are final and are no longer retried.

## Upgrade

If you see the "NVD rejected NVD.ApiKey" warning, request a new key at
https://nvd.nist.gov/developers/request-an-api-key or remove `NVD.ApiKey`.
Without a key, a full inventory scan of 120 lookups takes about 13 minutes.

Self-update replaces Invoke-PatchManager.ps1, which carries the whole fix.
Preserve the installed config, logs, reports, cache, and state. See
[the release guide](../RELEASING.md) for verification and rollback.

## Validation boundary

Automated preparation covers static/fixture tests on Windows PowerShell 5.1
and PowerShell 7, runtime validation of the example config, documentation checks,
PSScriptAnalyzer's zero-error policy, browser report tests, and package hash
verification. The rejected-key path was confirmed against the live NVD API
(404 with the key, 200 without) but the fixed script was not run end to end
against it. These checks do not install updates or validate real provider
behavior. No live-provider or publication success is claimed by this document.
