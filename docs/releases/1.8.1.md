# PatchManager v1.8.1

Prepared: 2026-09-06. Publication and live provider smoke tests are separate gates.

This patch release improves report reliability and operator follow-up. It
retains the existing patch-provider behavior, JSON/CSV shape, and exit codes.

## Changes

- Fleet reports reject malformed report shapes, invalid counters, and invalid
  provider flags without turning missing evidence into a healthy result or
  aborting the whole dashboard. Older reports may omit newer optional counters.
- Each host has a next step, with original notes available beside it. Missing
  evidence uses Unknown / Not assessed labels instead of reassuring clear states.
- Staleness uses unrounded elapsed time. Negative stale thresholds are rejected;
  report folders containing brackets are handled literally.
- Both HTML reports offer recovery from empty searches. Print output retains
  rows hidden by screen filters. Long mobile version strings wrap.
- Execution-lane totals count matching hosts, including script errors, once.
- Documentation now explains preview side effects, NVD inventory requests,
  timestamp-based fleet freshness, and full-package upgrades.
- Repeatable public-file packaging includes SHA256SUMS.txt and an external ZIP
  checksum. Browser regression checks cover desktop, tablet, mobile, printing,
  keyboard recovery, and no-JavaScript output.

## Upgrade

Deploy both scripts from the package to receive the device and fleet fixes.
Self-update replaces only Invoke-PatchManager.ps1. Preserve the installed config,
logs, reports, cache, and state; compare the example config and run ValidateConfig
before rollout. ExpectedSha256 pins the main script, not the release ZIP.
See [the release guide](../RELEASING.md) for verification and rollback.

## Validation boundary

Automated preparation covers static/fixture tests on Windows PowerShell 5.1
and PowerShell 7, runtime validation of the example config, documentation checks,
PSScriptAnalyzer's zero-error policy, browser report tests, and package hash
verification. These checks do not install updates or validate real provider
behavior. Windows 10/11 pilot smoke tests and publication must be recorded by
the release operator before rollout. No live-provider or publication success
is claimed by this document.
